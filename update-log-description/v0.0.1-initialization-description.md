# v0.0.1 Initialization Description

This document summarizes the initial SoccerRL setup on branch:

```text
RA_v0.0.1-initialization
```

## Goal

The first milestone is a small, debuggable 1v1 soccer sandbox that can be run
before any learning code is added. The current target behavior is:

```bash
python scripts/play_random.py
```

This opens a Pygame field, moves two random agents, scores goals, and resets the
episode after a goal.

## Environment Setup

The project uses Python 3.13.13 in a local `.venv`.

Python 3.14 was avoided because `pygame` attempted a source build on macOS and
failed due to missing SDL headers. Python 3.13 installs `pygame==2.6.1` from a
prebuilt wheel, which keeps setup simple.

Dependencies are listed in `requirements.txt`:

- `numpy`
- `pygame`
- `gymnasium`
- `pettingzoo`
- `pytest`
- `matplotlib`
- `tqdm`

## Current Environment Behavior

`Soccer1v1Env` is a PettingZoo-style `ParallelEnv` with two agents:

- `left`
- `right`

Available actions:

```text
0 stay
1 up
2 down
3 left
4 right
5 kick
```

The environment currently supports:

- reset and step flow
- sparse rewards
- goal detection
- score tracking
- episode termination after a goal
- circular robot collision resolution
- contested-ball pinning and relocation when both robots trap the ball
- out-of-bounds ejection and reward penalty when a player leaves the playable
  inner field line
- forbidden goal area boxes with reward penalties and ejection
- random-agent play
- manual keyboard control for the left player
- Pygame rendering
- headless `rgb_array` rendering for tests

## UI and Rendering

The renderer includes:

- green soccer field with subtle stripes
- center line and center circle
- team-colored players
- team-colored goals
- white goal area boxes around each goal
- compact scoreboard using matching team colors
- simple goal notification badge

Controls for manual play:

```text
WASD or arrow keys: move the left player
Space: kick
Escape, Ctrl+C, or window close: stop
```

## Physics and Tuning

Most tuning values live as module-level constants near the top of
`soccer_rl/envs/soccer_1v1.py`.

The current constants cover:

- field size and goal width
- goal area depth, width, and penalty
- playable field margin
- player max speed, acceleration, deceleration, and radius
- ball radius
- kick speed
- possession radius
- carried-ball contest radius (`TACKLE_RADIUS`)
- ball contest radius and stuck-ball relocation settings
- kick radius
- ball friction
- ball rolling resistance
- ball stop speed
- wall bounce
- out-of-bounds ejection steps and penalty
- goal area penalty
- render size
- team colors

Ball movement now has simple inertia plus slowdown:

- `BALL_FRICTION` applies proportional drag each frame.
- `BALL_ROLLING_RESISTANCE` subtracts steady speed while the ball rolls.
- `BALL_STOP_SPEED` snaps the ball to rest when it gets slow enough.

This keeps the ball from traveling too far after a kick while preserving a small
inertia feel.

Player movement also now uses simple velocity. `PLAYER_SPEED` is treated as the
maximum speed, movement ramps up through `PLAYER_ACCELERATION`, and releasing
input leaves only a tiny coast before `PLAYER_DECELERATION` stops the player.
Opposite-direction input resets that axis velocity to zero before accelerating
again.

Robots are treated as circular bodies for player-player collisions. When active
players overlap, the collision resolver separates them and removes closing
velocity along the collision direction, which keeps robots from passing through
each other.

## First Manual-Play Tuning

After manual play feedback, movement and possession were nudged toward a less
sticky, more futsal-like feel:

- Player speed was reduced to about two-thirds of the previous value.
- Player movement was changed from instant position steps to acceleration and
  deceleration around a maximum speed.
- The free-ball possession radius was reduced.
- Ball rolling resistance was lowered so kicks travel a little farther without
  increasing initial kick speed.
- A nearby opponent can now contest a carried ball instead of the owner keeping
  permanent possession.
- If both robots pin the ball between them for several seconds, the ball is
  relocated to a nearby safe playable spot.

This direction also fits a RoboCupJunior Soccer Entry / Infrared-style game:
robots chase and contest an accessible ball rather than carrying a fully locked
ball.

## Out-of-Bounds Rule

The pale inner field line now acts as the playable boundary for players. If a
player crosses it, that agent is ejected for a timeout, ignored by movement,
kick, possession, and contest logic, and receives `OUT_OF_BOUNDS_PENALTY` in the
step reward. The timeout is currently 300 steps, which is about 5 seconds at
60 FPS. The `infos` entry also records the out-of-bounds event and timeout
length so later RL code can use the rule cleanly.

## Goal Area Rule

White rectangular boxes are drawn around both goals. These boxes are forbidden
for players but not the ball. If a player enters either box, the agent receives
`GOAL_AREA_PENALTY`, is ejected for the same timeout, and the `infos` entry marks
the goal-area violation.

The current rules are collected in `soccer_rules.md` so gameplay changes have a
single human-readable reference.

## Ball Contest Rule

When a robot carrying the ball is pressed by the opponent, or when both robots
hold a free ball between them, the ball is pinned between the robot centers with
zero velocity and no owner. If that contested state persists for 180 environment
steps, about 3 seconds at 60 FPS, the ball is relocated nearby while avoiding
goal areas and both player bodies. The step `infos` dictionaries mark this with
`ball_relocated`.

## Validation

Current validation commands:

```bash
python -m pytest
```

```bash
python -m py_compile scripts/play_random.py scripts/play_manual.py soccer_rl/envs/soccer_1v1.py
```

The test suite currently checks:

- default constants feed environment attributes
- reset returns both agents and valid observations
- step output has the expected parallel-env shape
- goal rewards and terminations are correct
- kicked ball has inertia but stops within a short range
- player movement accelerates, coasts briefly, and resets velocity on reversal
- player collisions separate overlapping robots and stop closing velocity
- nearby opponents can contest a carried ball without bouncing it away
- prolonged ball contests relocate the ball to a safe nearby spot
- players crossing the playable field line are ejected and penalized
- players entering a goal area box are ejected and penalized
- ejected players ignore actions and reenter after the timeout
- rendered goals use the correct team colors
- rendered goal area lines are present
